## The scene digest's bound was false in three places, and the check that carried it was a clock race

**Timestamp:** 2026-09-16 17:00–17:40

**Action:** `f4e96f0` replaced `path\0size\0floor(mtimeMs)` with `path\0sha256(bytes)` in `sceneTreeDigest`, so the visual certificate binds the 44 frames to the served scene's bytes rather than its timestamps. Three statements of the old bound survived it: `docs/learning/gate-proofs.md:315` ("over file names, sizes and modification times, not contents"), `docs/learning/gate-proofs.md:356` (the re-derivation "has been watched to fire only against a file changed between the two hashes inside one synthetic run"), and `docs/devlog/detailed/2026-09-16_gate-integrity.md:35` ("over file names, sizes and mtimes, not contents"). All three are corrected here. The two learning-file lines are rewritten to the bound that holds now — the two digest values in entry (3) are values of the old algorithm and say so, and the "watched to fire" sentence now says the firing was a movement of names, sizes or mtimes, which is all the old digest could see. The devlog line keeps its original sentence and carries a dated correction marker naming `f4e96f0`, because `docs/devlog/` is history and the belief of the day has to stay readable. Entry (3)'s `**Bound**` now points at the new red control in the same file.

**Result:** the new red control drives the gate's own `--end` step over a synthetic 44-frame run and a served file rewritten from `one` to `two` — three bytes either way — with its mtime put back to the instant both arms share. Under the shipped digest the re-derivation moves `99e2bf99377f…` to `bc69cbe8d7d8…` and `certifyVisualRun` refuses: `The served scene data changed during capture, so these frames are not all pictures of the same city`. Under the pre-`f4e96f0` algorithm, reinstated verbatim and with the same probe, the digest is the same value before and after — `e77e3c7eaf497e0b…` — the check stays green, and the gate **certifies**: `All 44 fresh native-resolution frames survived the complete visual gate with matching hashes.` followed by `Certified run digest-proof: …`. That is the failure the content digest exists to prevent, and it is now a recorded red control rather than an argument.

The same defect seen from the other side: with the metadata digest back, the unit case that carries this bound, `test/visual-instrument.test.ts` "changes the digest when a served file changes", went **red 4 of 24 runs** (38.5 s total) from the same worktree, failing on the digest agreeing with itself — `expected 'c212f092a9346771a9856c3e82988439fbc72…' not to be 'c212f092a9346771a9856c3e82988439fbc72…'`. `f4e96f0`'s message records 1 of 12 on `main`. The two writes straddled an OS clock tick in the green runs and shared one in the red ones, so the old check was a race that the meter-moved condition won between one run in twelve and one in six; under the content digest the same case is deterministic and passes in 9 ms. **The unedited case is the gate** — this unit changed no test, and the entry records that.

Cost, measured rather than quoted: `sceneTreeDigest()` over this machine's served payload is 425, 427 and 447 ms for three calls, each over 137 files and 371,228,426 bytes, all three returning `0222c0566d507e4b…`. Two calls per gate run, so about 0.9 s of a three-hour run. **Correction, 2026-09-16 (round 31's review):** that payload no longer exists. The human agent set is missing from the rebuilt `data/`, so the served payload is now **84 files and 214,114,015 bytes, digest `ddd21ee1b4feb7f7…`**, and the figures above describe what was measured before the rebuild rather than the tree as it now stands.

**Reasoning:** the bound had to be re-proved at the level the gate acts on, not at the level of the helper. `sceneTreeDigest` is not what refuses a run; `assertSceneUnchanged` inside `certifyVisualRun` is, and a probe that compares two digest values by hand would have proved the helper and assumed the check. Driving `certifyVisualRun` is also what makes the defect arm say the damning thing — a certificate issued, not a predicate returning false. The mtimes are pinned on both arms because the defect is a race otherwise: in the wild a rebuilt tile that keeps its length may or may not keep its mtime, and a control that depends on the clock is the flake this unit is about.

**Validation:** the worktree's `tools/visual/verify-output.ts` is restored byte-for-byte after the mutation and `git status --porcelain` is empty. The probe writes its own 44 frames, manifests and three lifecycle records, so it needs no browser and no real scene, and the two arms differ only in the digest expression — the probe reads the algorithm out of the module source and prints which arm it is running. What the proof does not reach: it is a synthetic run, so the re-derivation has still never been watched against a real `npm run data:scene` executing during a real capture, and that remains written down as unproved in the entry rather than implied by this one.

**Code reviewer comments:** none — no independent review was asked for a unit that changes tracked prose and adds evidence, and none is claimed. The mutation is temporary and restored, which `git status --porcelain` shows rather than asserts.

**Notes:** only the path a file is served at and the SHA-256 of its bytes enter the digest, so the same tree gives the same value on every run and no timestamp, size or inode is covered — the probe measures the other direction too, moving the same bytes to a new mtime and leaving the digest where it was under the shipped algorithm while the old one moved. The old digest's run-to-run instability shows up in this unit's own log: two invocations of the defect arm over identical file contents reported `84ac93e2323e…` and `e77e3c7eaf497e0b…`, because the two files the probe never touches were written at different instants, while the shipped arm reported `99e2bf99377f…` both times. It covers exactly the two mounts `tools/vite/serve-scene-data.ts` answers, `data/scene` as `/scene/` and `data/network` as `/network/`, so data the app does not serve is outside it by construction; and no digest taken at two instants can report a file changed and changed back between them.
