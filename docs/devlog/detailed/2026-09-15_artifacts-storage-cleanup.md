# artifacts/ storage cleanup: 53.63 GiB of task evidence was 12 copies of a few things

2026-09-15. Worker session on the ignored evidence under `artifacts/`, which had reached 54,916 MiB (53.63 GiB) across 53 entries.

**The measurement trap is real and it is worth knowing before anyone quotes a size.** `git worktree` checkouts under `artifacts/` carry `data/` and `node_modules/` as junctions into the primary checkout, and every recursive tool follows a reparse point: `Get-ChildItem -Recurse`, `Remove-Item -Recurse`, `rm -rf` and git's own recursive delete. A naive total counts the primary checkout once per worktree — and the same class of command reaches *into* the primary checkout when it deletes. This session measured with `lstat` and never followed a junction; the eleven junctions it found are named by `npm run artifacts:size`, the check this session left behind.

**What the 53.63 GiB actually was.** Not gate frames. Nine worker worktrees had been created by copying a checkout, so each carried its own 1,430 MB copy of the ignored, regenerable `data/`: 12.9 GiB of bytes the repository already had. On top of that, the network lane's observer evidence was copied three to five times — `observer-v4-r2/root-r2-completion-20260913`, `observer-v4-r2/author-r2-completion-tests` and `observer-final/author-r2-completion-tests` are the same 16,826-file tree, verified by full inventory and sampled SHA-256 — and inside each of those trees **every PNG is the same 312,318-byte image**. One observer case directory holds 144 files and 19 distinct payloads: 126 copies of one frame across 18 view directories, because the capture wrote the same image for every view. That is why 105 cases weigh 4.5 GB per copy.

**Trace retention was already correct, and was not the cause.** `trace: "retain-on-failure"` has been in `playwright.config.ts` and `playwright.lifecycle.config.ts` since the scaffold commit `74d0df1`. A passing lane leaves no trace at all: after the last passing pixel-lane run, `artifacts/playwright-report/` holds `index.html` and nothing else. The 100-160 MB zips are retained *failures*, which is deliberate policy, and they are 1.5 GB of the 53.63 GiB — 2.8%. Changing `trace` would trade a real diagnostic for 2.8%, so the fix went to duplication instead.

Reclaimed 29,119.2 MiB (28.4 GiB, 30.5 GB): 15,065.7 MiB of duplicate observer trees, 12,870 MiB of copied `data/`, 546.2 MiB of uncited traces and 637.3 MiB of duplicated candidate inputs. `artifacts/` is 25,797.0 MiB (25.19 GiB) after, with the live gate, the four dirty worktrees and every path a tracked document names left in place.

What it cost: running a gate inside one of the nine affected worktrees again needs `npm run data:fetch && npm run data:scene`, or a junction to the primary `data/`. What it did not cost: any file a tracked document names by path. `r2-freeze.json`, the file review 15 pins, keeps its `author-r2-*` records; the two cited failure traces (`2c2a999046828303…`, `bfe38eb460337416…`) stay; review 19's `worktree/artifacts/playwright/…/trace.zip` stays.

Left deliberately, and the largest thing left: `artifacts/network/response-review-r2/replay` (7.6 GiB) and `response-review-r1/replay` (2.8 GiB) are the reviewers' own independent reruns of the R2 response and completion checks. Review 15 says of that checkpoint that raw fixtures and run inputs must be retained until a later reviewed source target makes them recoverable, and the replay trees are the reviewers' runs rather than copies of the pinned trees — so they stay until that checkpoint closes. That is 10,642.6 MiB (10.4 GiB) waiting on a decision no worker here can make.

Full survey, deletion log with per-entry verification, and the rule text: `artifacts/storage-cleanup/REPORT.md` and `DELETE-LOG.md`. Check: `npm run artifacts:size`. Rule: the new paragraphs under `## Gate artifacts live in artifacts/` in `docs/policies/local-rules.md`.
