## The bake's verification was a paragraph; it is now a tool with a control per defect class

**Timestamp:** 2026-09-16 19:20–20:10

**Action:** `docs/work/0_shibuya-1km/plan.md`'s post-capture runbook restores the human agent set with `npm run data:agents` and then asks the next session to "verify the bake rather than assuming it": three variants at three LODs with `glb`, `positions.f16` and `normals.f16` beside a manifest, plus the three source blends — 33 files — and the three manifest names `src/world/agent-assets.ts` requests. That was a paragraph carried out with the eyes, and the set is exactly what a worktree removal destroyed on 2026-09-16 when it followed a `data/` junction into the primary, with `data:agents` outside `data:setup` so the rebuild could not restore it.

The expectations were derived from the code before the tool was written, and the code agrees with the paragraph. `tools/agents/bake-human.py` sets `OUT = ROOT / "data/scene/agents"` (line 20) and writes `{variant}-{lod}.glb`, `{variant}-{lod}-positions.f16`, `{variant}-{lod}-normals.f16` and `{variant}.json` (lines 360-369, 437) for `near`/`medium`/`far` (`build_variant`, line 417). `tools/agents/build-human.py` writes `{variant}-source.blend` into the same directory (line 104), which `build_lod` reopens per LOD. `HUMAN_ASSET_URLS` requests the three manifests by name at `/scene/agents/`. 3 variants x 3 LODs x 3 files + 3 manifests + 3 blends = 33. **The paragraph and the code agree, including the count.**

`tools/agents/verify-human-set.ts` is that check. It takes `--root <directory>`, defaulting to `data/scene/agents`; requires each of the 33 files non-empty; parses each manifest and fails by name when it is missing, empty, not JSON, or carries no `lods`; requires every file a manifest names to be a bare file name (not a path) to exist beside it, to be non-empty, and to match the SHA-256 the manifest records; names a digest field that is present but malformed; names a recorded `bytes` that disagrees with the three files together; names a LOD a manifest stopped declaring; names a missing source blend; and exits 1 with a summary that lists the failed variants and LODs. The variant list is read out of `HUMAN_ASSET_URLS` rather than restated, so a fourth variant or a renamed manifest changes the check instead of escaping it. Files it does not name are listed and do not fail the set, because `vehicles.json` and the three vehicle GLBs live in this directory too; a file named the way the bake names its output but absent from the set is reported as a finding, which is what a half-rename looks like. It reads nothing under `data/agents/source` and runs no bake.

**Reasoning:** two of the eleven reds found defects in the check rather than in the tree it was reading, and neither would have been found by a single mutation.

The first was a **false red that hid every real finding**: the manifest's `bytes` is written by `bake-human.py` (line 377) as the three files added together, and the check compared that number with each file's own size, so a correct synthetic bake produced **27 findings across all 9 LODs** and a real message would have arrived buried in two dozen invented ones. `bytes` is now checked against the sum of the three files, and only when no per-file problem was already reported for that LOD.

The second was a **false green on a corrupt manifest**: `recordedDigest` returned nothing for a value that was present but not 64 hex characters, and "nothing recorded" was then read as "nothing to check", so a manifest carrying `"not-a-digest"` passed. A digest field is now three-valued — absent, a digest, or malformed — and the malformed case is a finding that says why a digest that is not a digest cannot be compared with anything.

Both are the same shape as the rule that a gate cannot tell "passed" from "did not run": the check was reporting the second as the first, in one direction by inventing failures and in the other by dropping one.

**Code reviewer comments:** none yet — no independent review has read this revision, and the tool has never been run against a real bake. One defect was found here rather than by a reviewer, and it is a property of where this unit runs: on a loaded machine, the suite is flaky against vitest's default 10-second ceiling. The same file that passes in **4.7 s** idle failed **4 of 14** on a run that shared the CPU with the capture, at a wall clock of **41.5 s** — the three heaviest inventory cases and the subprocess case, each by timeout rather than by assertion. Every case that touches a tree now declares a 120-second ceiling of its own, so a check that is merely waiting is not reported as a check that failed. The independent check that does exist is the second implementation of the same contract already in the repository: `tools/agents/verify.ts` decodes the VAT files, checks the half floats and runs the shipping admission gate, and `tools/agents/manifests.ts` re-derives `drawParts` from the delivered GLBs. Both are the stronger check on a populated directory and neither is subsumed here; this tool is the inventory step that runs first and refuses an incomplete set before either of them tries to load one.

**Notes:** what remains unverified is the run this tool exists for. `data/scene/agents` holds only `vehicles.json` and the three vehicle GLBs, the machine is owned by the verdict capture, and writing 33 files into a served mount would move the scene digest the certificate re-derives at `--end` and refuse three hours of frames. So the synthetic trees prove the check and prove nothing about the bake's output — whether a real bake's manifests record the digests of the files beside them is exactly what the first post-capture run will say. The tool also cannot check the source blends beyond presence and non-emptiness: a truncated `.blend` is not detected by a byte count, only by Blender reopening it.

The three source blends being required is the one part of the runbook that no runtime path reads — nothing loads them, and the bake only needs them while it runs. They are checked because the plan names them as part of the 33 and because they are the only artifact from which the accepted rigs can be re-inspected without the 325 MB of pinned archives; a missing blend therefore fails the set while saying exactly that, rather than reporting an asset count nobody asked about.
