## R31 — P2: required numeric fields still accept other JSON types

**Location:** `ShibuyaWorld.cpp:213`, `:236–241`, and the adjacent record-size reader `:174`, through the existing `Number` and `ReadPoint` helpers at `:63–68` and `:95–103`.

`SameJSON` correctly compares actual JSON types before comparing values. The separate schema readers do not. `Number` uses `TryGetNumberField`, and `ReadPoint` uses `TryGetNumber`, without checking `EJson::Number`. Installed Unreal primary code confirms these methods deliberately coerce values: `Json/Private/Dom/JsonObject.cpp:420–423` delegates to `TryGetNumber`; `Json/Private/Dom/JsonValue.cpp:476–479` converts booleans to 1 or 0; `Json/Public/Dom/JsonValue.h:451–461` parses numeric strings.

Consequently, a support manifest with `schema_version: true` or `schema_version: "1"` satisfies the new version-1 check. If both compared source/support derived records carry the same string-valued triangle/vertex counts or string/boolean coordinate entries, their structural equality can correctly succeed while their field schema remains invalid; the later coercive readers still accept those values. Newly admitted record byte counts can likewise be numeric strings. This is a distinction between equality of two supplied records and conformance of each record to its required schema. It is not a defect in the recursive type guard itself.

The byte/hash chain still rejects an un-receipted edit. The malformed-field condition applies after the enclosing records and hashes are internally consistent, so it should be tested at the typed-admission boundary rather than stopped earlier by an unrelated hash mismatch. No native malformed-field control was run during this review; the finding is grounded in the exact authored call path and installed conversion implementation.

**Required repair:** require actual numeric JSON types for the new support schema version, derived counts, each bounds coordinate, and newly required record byte counts before their existing finite/integer/range checks. Keep valid source values, thresholds and geometry unchanged. A focused control should admit the valid numeric form and reject boolean and numeric-string forms through the production admission path. This blocks claiming the requested strict typed manifest admission is complete; it does not establish a memory-cap bypass or a wrong native ground measurement.
