## Findings

**[P2] Require literal JSON types in native frame admission.** `Source/ShibuyaRuntime/Private/NativeFrameJson.h:17` accepts `schema_version` through `TryGetNumberField`, which converts rather than checks its JSON type. In the installed UE 5.8.3 source, `JsonObject.cpp:420–423` delegates to `FJsonValue::TryGetNumber`; `JsonValue.cpp:476–479` maps JSON `true` to numeric 1, and `JsonValue.h:451–456` maps the string `"1"` to numeric 1. Either value passes `NativeFrameKnown` when the other two fields carry the current ID and seal. This contradicts the exact three-field typed record required by the shared frame contract and the Python producer, which explicitly rejects a boolean schema. The portable tests call `NativeFrameKnown(double, ...)` and cannot detect this coercion. Require `EJson::Number` for schema and `EJson::String` for ID/seal before conversion, preserving the three-key and exact-value checks. Add a regression through the actual JSON admission helper for the current literal record and missing, old, extra, boolean, string, and unknown schema variants. This needs a focused re-review and affected checks; it does not require changing physics, source data, or tolerances.

**[P2] Enforce the new frame on native reports and reusable receipts.** At the orchestrator's request, this review also inspected the narrow report-admission path in existing `tools/runtime/run_native.py`. The file contains no `native_frame` check. `validate_arm` at lines 272–327 accepts a fresh run ID/time and gameplay predicates without a frame, `complete_probe` at lines 258–269 does not check snapshot frames, inventory admission at lines 681–692 only binds hashes, and `validate_prerequisite` at lines 495–501 does not admit a frame. The runner does bind the actual DLL hash, so an old receipt with a different DLL is rejected; that does not prove a freshly run DLL implements the current headers. A fresh old-binary report can lack the new record while the outer receipt records current source hashes. The new C++ report marker therefore does not yet enforce the required old/mixed refusal class at this boundary. Add a strict current-record validator at native report, relevant consumed snapshot/state, inventory-preparation, and prerequisite receipt admission, and emit the current record in the outer receipt. The report-write-negative arm has no native JSON; preserve that intentional absence while versioning its outer receipt. Cover missing, old, wrong-seal, extra-field, boolean-schema, and mixed-state records with focused runner tests. This is a bounded validator/test repair, not a request to redesign the runner. The actual two-target build report reviewed below remains valid evidence for its own exact binaries.
