## Material findings

**R1 — note-property subclasses cross the claimed no-getter boundary.** In `stable-sort-inner-cost-v2/CensusStableSort.cs`, lines 49–54 accept `property is PSNoteProperty`, then read `path.Value`. That accepts subclasses rather than exact note properties. The deployed, pinned SMA metadata independently shows `PSNoteProperty` is nonsealed and its `get_Value` is virtual and nonfinal. The actual assembly also contains `PSVariableProperty : PSNoteProperty` with its own nonfinal virtual getter. Therefore a custom subclass with a counting, changing or throwing getter passes this admission test and can run during the purported safe path. This is a static dispatch consequence, not a runtime counterexample or a claim that the current JSON descriptors contain such a property.

The same material hole exists in byte-identical v34/v35 `CensusTypedTreeV31`: `CensusOptimized.cs:144` accepts subclasses in `Keys`; `Supported:174` calls `Get:154`, which reads the virtual `.Value` during domain validation. A subclass getter can run before the complete domain has been validated; a thrown ordinary exception would also bypass the `UnsupportedTree`-only fallback result. Thus the earlier bounded review does not establish the advertised no-getter admission bound for arbitrary subclass rows. The recorded JSON-only typed comparisons remain separate positive evidence and are not retroactively described as failed.

The deployed SMA evidence is `sma-metadata.json`: 19,646,264 bytes, SHA-256 `2d8af026e589c5603629bfc3e7c57265b4167b12eca3ae549c6a6c3ca7e4967b`, MVID `42bb522b-1082-4dc3-92f1-94f47317bb85`. The review reads PE/CLI table data without loading or executing this assembly. Public source corroborates the extensible shape and existing subclass, but is not asserted to be the exact deployed patch: [PowerShell member source](https://raw.githubusercontent.com/PowerShell/PowerShell/master/src/System.Management.Automation/engine/MshMemberInfo.cs).

Repair acceptance: reject any custom-object property whose runtime type is not the exact admitted inert note-property type before reading its value. Add a subclass whose getter increments a counter and a throwing variant. Both helpers must return UNSUPPORTED with getter count zero. Exercise whole-root original fallback separately and allow the original semantics to observe the getter there. For typed trees, put the subclass after an earlier mismatch on either side as well, retaining complete-root validation. Re-run the existing ordinary literal and actual JSON controls on the exact repaired bytes. Do not weaken the fallback, canonical conjunct, guard, caps or denominators.

**R2 — wrapped-container extension rejection is incomplete.** `CensusStableSort.cs:32–34` excludes note, script and alias properties on a wrapped root, but omits `PSCodeProperty`. The same three-type exclusion appears in v34/v35 typed-tree `Unwrap:118` and `Supported:162`. The stated contract excludes extended containers; the code does not exclude every extension kind. An extended `Length`/`Count` on the sort root, or `Count`/`Keys` on a typed array/dictionary, is relevant because the original PowerShell bodies use those property lookups while the compiled bodies use raw array/dictionary members. No such counterexample was executed in this read-only review, and the current 887 JSON rows do not establish this boundary.

Repair acceptance: make extension admission explicit and complete, rather than merely add one blacklist entry without accounting for other property kinds. Add counting `PSCodeProperty` controls on a wrapped exact object array and the typed array/dictionary cases. The accelerator must refuse before invoking the getter, then the original whole-root fallback must be exercised separately. Plain JSON roots must retain supported status. These are part of the same closed-domain contract as R1.

**R3 — the remaining profiler needs two missing values, not one.** `probe.ps1` never initializes `$InventorySHA` or `$actualManifest`. The first omission explains the observed line-114 immutable-state refusal; the exact pinned receipt fields agree with the approved inventory hash in the static diagnosis.
