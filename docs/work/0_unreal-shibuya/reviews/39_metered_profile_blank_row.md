## Why the native row is valid, and what the repair proves

Installed `GPUProfiler.cpp:480–481` writes Name with three spaces per hierarchy level. Its table writer auto-sizes the column and pads each cell (`554–580`, `650–658`). An empty Name therefore becomes all spaces in the fixed-width event cell: its hierarchy depth cannot be recovered by counting those spaces. This is actual information loss in the text format. The previous parser's empty-name reset at that point caused subsequent non-root rows to be dropped, explaining the observed missing-pair refusal without implying that the renderer omitted histogram work.

The native source provides a safe constraint for this particular row. `GPUProfiler.cpp:264` and `276` add dispatch counts; `1692–1702` adds each event to the current node's exclusive count and every ancestor's inclusive count. A node with zero inclusive dispatch cannot be an ancestor of a later positive-dispatch descendant. This is a necessary relationship established by installed code, not a relationship inferred from the expected histogram labels. Primary source SHA-256: `491d174fe878e8dac49af70063a8cffe14bf13d9fda9d196f1e35c4df3c0f942`. All eleven installed-primary hashes recorded in the new receipt were independently checked.

For zero inclusive dispatch it enumerates every legal current prefix/depth and preserves the unknown node's occurrence identity. It does not simply keep the prior stack or guess the blank's level. A positive-inclusive blank clears candidate ancestry; it is not used to reconstruct proof. More than 128 prefix alternatives raises a did-not-run error.
