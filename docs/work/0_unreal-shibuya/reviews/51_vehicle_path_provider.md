## Material finding R51-1: bind consumer headers and station partitions before certification

Priority P2; material for this preparation's independent certificate and readback acceptance. Primary locations: `certification.py:133`, `certification.py:148`, `certification.py:171`, `certification.py:186`, `certification.py:188`, `certification.py:199`, `certification.py:205`; consumer locations `readback.py:9` and `readback.py:25`; construction locations `provider.py:89`, `provider.py:99`, `provider.py:137`; missing mutation coverage `controls.py:36` and `controls.py:66`.

The consumer chooses modulo, range and original-station lookup using `record.closed`, `new_xy_length_m`, `original_length_3d_m`, and `old_unwrapped_origin_3d_m`. The independent certificate never reads `record.closed`, `new_xy_length_m`, or `old_unwrapped_origin_3d_m`. It correctly checks the Source route's closure and recomputes `original_length_3d_m` from immutable raw XYZ, but this does not bind the other serialized values used by readback. Consequently, changing only a valid closed packet's total XY length to half the true length leaves every certificate predicate unchanged while making `sample_xy` wrap in the middle of the route. Changing only an open packet's `closed` flag to true leaves its Source-based endpoint certificate unchanged while making the consumer wrap at its exit back to its entry. Changing a closed packet's origin from its positive first mapped station to zero can leave station zero outside all stored intervals. These are finite, JSON-representable metadata-only counterexamples established by reading the call paths; they have not been executed.

The adjacent station partition has a separate instance of the same trust gap. For a multi-primitive block, the constructor sets each `block_part_xy_interval` from actual accumulated primitive arclength and `block_xy_length` from their sum (`provider.py:93-109`). The certificate checks a declared interpolation ratio and old/new continuity, but never reconstructs this block partition from the primitives (`certification.py:188-203`). In any otherwise valid multi-primitive junction block, moving one internal old-station boundary and the corresponding shared declared partial-XY boundary preserves geometry, anchors, new-XY intervals, total old span and old continuity. Its declared interpolation ratios remain self-consistent. Only the first/last actual block endpoints are checked against their anchors. The consumer can therefore receive a different old-to-new allocation under the same geometric certificate. Checks must establish the true consecutive block membership, full block length and each cumulative part interval, rather than accepting an internally consistent declaration.

There are also missing type/finite guards before station arithmetic. `a`, `b`, `na`, `nb`, `ba`, `bb`, `pa`, `pb` and `block_length` are unpacked without `finite`. Ordered tests and `abs(error) > limit` do not reject NaN: for example, replacing only the terminal `new_xy_m` endpoint with NaN makes its comparisons false and has no next interval to catch the bad start. The direct certificate can return `proven: true` with a nonfinite final XY length. The actual probe's `json.dumps(..., allow_nan=False)` at line 82 blocks that particular nonfinite serialization before its post-JSON certificate; this is not a claim that the frozen probe currently emits JSON NaN. The finite header and block-part counterexamples above do cross that JSON boundary. Zero/negative/header-type values also need explicit rejection before modulo/division rather than incidental exceptions, clamping or truthiness. The existing source-derived original-length comparison at line 148 must be retained; it already rejects a changed finite old length for these sources.

Required repair: validate that serialized closure is a real Boolean equal to immutable Source closure; bind finite positive total XY length to the actual primitive sum and final XY station; bind old total to the independently recomputed raw-XYZ sum; bind the finite unwrapped origin to the first validated old interval and the appropriate open/closed range. Independently reconstruct every station block's complete primitive partition and verify every serialized interval against it. Apply strict numeric/type/finite checks before comparison or arithmetic to every consumer range, modulo, origin and interval field, rejecting Boolean-as-number and malformed scalar types. Keep all current numerical limits, monotonicity, Source anchors, full-span, body and conservation checks.

Required controls: use the real post-serialization certificate and ordinary readback on independently specified positive open and closed fixtures. Mutate only one header, or only the paired station-partition metadata needed for the second counterexample, leaving primitive bytes and immutable inputs unchanged. Cover wrong closure, half/doubled/zero/negative totals, changed old total, shifted origin, malformed numeric types, nonfinite scalars, terminal interval corruption, and a finite internal multi-primitive station split. Show that the old checker accepts the relevant finite mutations and the repaired checker refuses them. For nonfinite cases, distinguish strict JSON rejection from direct certificate rejection. Retain genuine positive closed-seam, open-endpoint and original-station readback. The present 34 controls do not exercise these classes: reversing an interval or changing a Source-sequence anchor is insufficient. No bound widening or raw-rail fallback is part of this repair.
