# Before-code contract 2 — finite actual factory/class association

This is a proposal for Root adoption, not code or an execution lease. Keep all selected defining-module globals, identical retained compile-code, raw class/descriptor, defaults/kwdefaults/closure and later identity checks from contract A. Preserve ZipMember/property/contextmanager/original-call branches, guarded read1 and primary-before-formatter behavior. Original32 proofs/quotas,24x2/prior108/P1, maps/native cohort and all clocks remain unchanged.

## Explicit contract changes to decide

E1: replace the universal ClassDef-only premise with an explicit association sum: actual selected ClassDef acquisition OR an actual finite registered factory/class-creation receipt. A factory receipt must identify the exact returned class and its source call/class body. Missing both remains RED. A selected-owned function on a generated class still needs a valid class association; identical owned function code by itself does not silently excuse an unknown class origin.

E2: add collections.namedtuple receipt eligibility at the three exact direct module-assignment sites ArgSpec, _Version and PPaths, using the immutable source pins, AST locations and literal typename/field/options in the manifest. The two other namedtuple call sites are inventoried but not included in initial module-export admission. No arbitrary namedtuple instance or tuple subclass is accepted.

E3: add a typed delegation receipt for the19 exact direct typing.NamedTuple source declarations. The3 statically derived NamedTuple classes remain normal source-ClassDef associations plus any actually required inherited behavior; do not treat all inherited methods as raw injected slots. Admit no generic/metaclass variation solely from a base name: the actual source body, metaclass/delegation path and returned class must satisfy the finite receipt.

E4: decide a finite Protocol route for all11 exact source declaration candidates, including subscript/generic bases. Its initially proposed runtime roles are the actual _proto_hook and _no_init_or_replace_init objects; unexpected raw Python-function roles remain RED. This is an escalation from the previous three explicitly unknown PIL classes, not a claim that they have now passed.

E5: decide whether to extend Enum/IntEnum eligibility from12 to the31 exact source declarations and separately whether the5 IntFlag declarations are in scope. The existing Enum/IntEnum two-role ownership remains intact. IntFlag would require explicit live Flag/IntFlag adoption and exact additional operator-provider roles derived from the pinned EnumType source, then observed in actual units. No IntFlag slot set or raw descriptor kind is presumed from the provider. Keeping this escalation on HOLD is valid, but a full Source run cannot be used as its first undisclosed import test.

E6: the unrelated NumPy test dataclass and11 dynamic type sites are inventory entries, not new admitted categories. The module-loop SIMD classes have no function members in their displayed construction attribute dictionary, but their live raw slots were not observed; do not turn that static observation into a runtime exemption. Function-local type classes are outside initial exported-slot admission. Any encountered unknown remains RED. New eligible type(...) behavior would need a separate finite call receipt, not deletion of association checks.

## Actual lineage required

Before selected factory use, explicitly adopt the live collections/typing/enum modules and actual provider/factory/metaclass objects, functions, code, globals, defaults/closures and descriptors. Retain/recheck their registrations and original bindings. This is a declared bounded stdlib startup trust assumption. Source hashes are integrity/review context, not initial source-versus-pyc/vendor/ABI proof. Capturing objects after their use or reloading/recompiling expected functions is insufficient.

At an eligible source site, bind the actual caller module/class-body frame to that selected acquisition's identical code object and globals, the exact unique AST call/class location and actual arguments/namespace. Retain the actual provider entry, delegation and returned class. No class label or two rewritten metadata aliases can substitute for those objects. A source decorator that relabels a class must leave the actual returned class identity linked to the same source receipt.

For namedtuple, observe the real eval operation in the actual provider frame, its actual expression/namespace and actual produced compile/function objects. __new__.__code__ must be the identical lambda descendant of the actual executed eval code, with the actual namespace; do not regenerate an expected lambda. Bind the other actual generated function codes to the actual live factory's nested code and their real globals/closure values. Retain the actual type-created class, namespace-to-result function mapping, returned raw descriptors/kinds and alias relationships such as _replace/__replace__. Actual produced special descriptors are measured, not inferred from input provider kind. Later module/alias/class/raw slot/provider/function/code/default/closure checks must refuse replacements.

For class-syntax NamedTuple, also bind the actual selected ClassDef body namespace and actual typing.NamedTupleMeta.__new__ -> _make_nmtuple -> collections.namedtuple path. Preserve actual fields, defaults, annotations and user methods; user methods still require selected acquired-code identity. A Generic helper is a separate actual provider role requiring explicit review/negative control if observed. Unexpected methods, bases, callsites or helper roles stay unknown.

For Protocol, bind actual selected class creation and actual _ProtocolMeta/Protocol.__init_subclass__ execution, actual base/metaclass objects and copied provider objects. The raw _proto_hook descriptor starts as a classmethod in the pinned source; that fact does not establish each subclass's actual raw descriptor. Retain real output descriptors and verify actual underlying function/provider identities. Keep selected-owned method and property boundaries unchanged. runtime_checkable changes must be bound where declared rather than trusted as an arbitrary decorator.

For Enum/Flag, keep existing selected class/source association and actual provider function/code/globals proof. Added source entries and any Flag roles require their own exact live provider/creation observations. A family name, inherited filename or matching function text never suffices.

## Hook composition and fit are part of the decision

The preferred prototype is a small scoped receipt using the existing accepted actual-call/return/code lineage pattern. It should activate only around actual registered factory/class creation, rather than keeping a new profile hook active through unrelated module imports. Typed NamedTuple delegation must be one composed owner, not nested competing profile hooks. Existing ZipMember requires its hooks untouched; no new receipt may hide a pre-existing hook or consume that proof. Exact before-code hook arbitration/restore paths must be reviewed before implementation. If this cannot be done within the existing acquisition architecture, return that concrete gap instead of adding a general runtime framework.

The simpler alternative, a globally active import profile dispatcher, has broader hook/cleanup interaction and is not proposed for automatic adoption. Skipping runtime methods, trusting self-baselines or recompiling providers is rejected. The shared-helper/receipt mechanism remains unproved until genuine actual-definition controls observe it. Added startup work has no demonstrated headroom under17; P1 must measure all actual acquisition/receipt work before any new full32 lease.

The finite manifest is a maximum review population, not an instruction to import unrelated test modules or admit every candidate. Root must choose exact enabled entries/provider roles before code. Each enabled entry needs actual receipt-based admission; each disabled, conditional, ambiguous or unexpected entry remains unadmitted. A source/library pin change invalidates the manifest. No new Source mode/carrier, physical clock, permission, case or vendor-completeness claim is authorized by this proposal.
