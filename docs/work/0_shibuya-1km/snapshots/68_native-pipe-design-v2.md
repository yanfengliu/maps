## Native state and exact release points

Use one per-environment native control block. It contains no JS value that a background thread can access. No napi_env, callback pointer or TSFN authority is shared with the parent environment. The same addon binary and native pipe body serve Chromium, the first three native controls and N04. Test barriers and peer configuration may vary; teardown must not select an alternate implementation.

The native control block has explicit ownership leases, separate from TSFN thread-count acquisitions. Keep the two ledgers distinct. Every callback payload receives a stable ID and one native lease before enqueue is attempted. Its lease keeps both its bytes and the callback context/control block valid through the entire callback frame. A channel-finalizer lease protects the finalizer's context. Hook and native-producer leases protect those users until their final accesses. A per-environment instance-data lease anchors public addon entry points; its finalizer releases only that lease. The smallest proposed interface uses this one per-environment scope, without extra raw-pointer JS wrappers. If implementation introduces another such wrapper, it must declare and verify its own lease. A native callback frame never accesses the block after releasing its last lease.

| Holder or result | Ownership and terminal action |
| --- | --- |
| Cleanup hook | Acquired when registration succeeds, before producer start. Held until native dependencies are joined and hook removal returns. A failed registration rolls back owned construction; it never starts unregistered work. |
| Environment instance | Held from successful per-environment initialization until its native instance-data finalizer's last access. That finalizer records and releases only this lease, without JS or a join. Its order relative to channel/payload finalizers is not assumed. |
| Native producer | Native lease and its own TSFN acquisition exist before the thread starts. The producer stops enqueue attempts when stop is latched. Its last TSFN action is release, or a call returning closing; never both for that acquisition. The joiner holds the producer's native lease through thread exit and the join record, then releases it. |
| Channel controller | A distinct TSFN acquisition exists from construction. Only the environment-side controller releases it, after producers can no longer access the TSFN. It is not borrowed from a producer and is not reacquired during stop. |
| Successful enqueue | `napi_ok` transfers payload-disposal responsibility to the callback path. The accepted payload's native lease remains live until one delivered, callback-error or teardown-discard terminal record. The hook must not free this queued payload. |
| Queue full | Payload was not transferred. Producer records the exact status, retires its own payload/lease once and latches failed work plus native stop. No blocking enqueue, retry loop waiting for JS, silent drop, or success. Already accepted IDs still need their own terminal records. |
| Closing result | The unaccepted payload is retired by the caller once. Its TSFN acquisition is recorded as consumed by closing, then the caller makes no further TSFN API call—not even a second release. Its native lease remains until that producer really exits. |
| Other enqueue failure | Payload remains caller-owned; record status, retire it once and fail/stop. Retain the caller's TSFN acquisition until its permitted final release; an unknown status is not silently treated as closing. |
| Callback with usable env/callback | Hold the payload lease through copy, any JS call, exception capture and terminal native record. Release the payload exactly once after the last access. A JS exception is retained independently and cannot turn delivery into clean success. |
| Null env or callback, or teardown latch | Call no JS or environment-dependent API. Record teardown discard, retire bytes and release the payload lease once. This path may run after the channel finalizer. |
| Channel finalizer | Record finalizer observed, release only its own native lease, and make no JS call or join. Do not free queued payloads or assert native state is dead. Accepted-payload leases survive it. |
| Last native lease | Destroy the block only after hook removal, producer join, channel-finalizer observation, environment-instance release, every accepted/unaccepted payload disposition and zero active callback frames. Emit native destruction accounting before the final access ends. No destructor uses the TSFN or JS environment. |

Register the manual cleanup hook after creating the TSFN and before starting native producers. Preserve actual hook/channel event ordering in the proof rather than relying on registration order as the verdict. Source review must trace each acquisition/release and all failure exits. A thread that relinquished its TSFN authority may still use its separately held native ledger to report exit, but may never call the TSFN again.

## Dependency-safe shutdown

The hook uses the same native stop/drain body as ordinary close. Its entry and completion records identify the cause as environment teardown. It never calls the ordinary JS requestStop wrapper, waits for a JS promise, waits for a queued JS callback, or waits for a finalizer scheduled after the hook. Finalizers never join the producer. This removes both possible cycles.

1. Latch stop and reject new acquisitions/sends. Release any test acquisition barrier through its cancellation path. Stop callback production without requiring JS progress. A native thread already in a nonblocking TSFN call must return and record its actual result; it is not abandoned.
2. Request cancellation for every outstanding read/write and request child stop only through the retained original process/job authority. Keep OVERLAPPED structures, events, buffers and pipe handles live. Cancellation request, actual completion, root wait and successful job-zero query remain separate records. A normal-completion race is retained.
3. Settle every native I/O operation and join the native producer. The environment hook may wait on these native dependencies on its own thread, because none requires JS or the callback-channel finalizer. It must not hold a mutex needed by the producer while waiting. Native receipts continue through the independently drained diagnostic channel. A stalled join remains nonfinal; the outer deadline may score failure and rescue, never manufacture a clean receipt.
4. Retire unsubmitted/caller-owned payloads, close the now-safe I/O storage/handles and release the channel-controller acquisition with abort after producer authority is gone. Any producer acquisition previously consumed by closing is not released twice. No producer or hook TSFN access follows its last release. Accepted queued payloads retain their leases for Node's callback disposal; neither producer join nor channel release proves they have been freed.
5. Remove the async cleanup hook once, on the environment thread, after those native dependencies are safe. Preserve the result and relinquish the hook lease after its final access. **Do not wait here for channel finalization, queued-payload disposal, destroyed-environment JS settlement or control-block destruction.** Those may follow removal. Hook completion is a partial receipt, not full drainage.
6. Allow Node's finalizer and null-env callback disposal to run. The control block and each payload remain valid according to the lease table, including exact-version finalizer-before-emptyqueue ordering. Only the independent receipt observer can combine finalizer, every payload terminal record, control-block destruction and Worker/environment completion into the complete teardown observation.

Ordinary close retains live-environment delivery and SDK settlement rules from v1. A JS callback or drained promise cannot certify its own callback channel's destruction; the final native receipt is authoritative for that field. The data-only environment-instance lease may remain after ordinary resource drain until natural environment exit; it does not keep a TSFN or native operation active. C01 now also requires the case's Node process to return naturally after ordinary drain, with original-handle wait and actual exit code. No process.exit, forced kill, early TSFN unref workaround or outer rescue may satisfy that condition. Full receipt after natural exit remains distinct from the earlier JS operation result.

## N04: actual environment destruction with live outer owners

This is one additional native control with one Node Worker and one native pipe peer, no Chromium or SDK attempt. The native outer driver creates the Node parent host under the existing atomic outer job and retains its original process handle. The host creates the Worker using the same addon binary. Keep addon state per environment; the parent host does not need to load a second native module or inherit Worker napi_env objects.

The Worker starts the same native pipe body with the peer used for the pending-write control. The peer emits the fixed JSON objects `{"proof":"N04-A"}` and `{"proof":"N04-B"}`, each followed by one NUL byte, confirms on its separate native control acknowledgment that it will consume no command bytes, and remains alive. That acknowledgment is not a third callback payload. Native code requests the same 4 MiB write and arms a read after receiving the replies. The Worker enters a test-only `Atomics.wait` on a SharedArrayBuffer in the same JS turn that arms the native body; it does not run requestStop or yield an event-loop turn that could drain the callbacks. A TSFN queue capacity of two is declared for this fixture. The two reply payloads must be accepted; the fixture does not enqueue a third or silently suppress queue-full behavior. This is a callback-delivery barrier, not a replacement cleanup path.

The outer driver must independently see, before sending the trigger: actual pending read and pending write (`ERROR_IO_PENDING` and nonfinal `ERROR_IO_INCOMPLETE` receipts), two accepted payload IDs with zero callback-entry/terminal records, both payload leases outstanding, native peer originally unsignaled, and the parent Node process originally unsignaled. It keeps draining native receipts while the Worker's JS is blocked. Missing, already-settled or empty-queue checkpoints make N04 unavailable/failed.

Use the existing outer driver's dedicated Node stdout pipe for compact native diagnostic records, written from C++ with a native serialization lock. That process-host-owned writer is borrowed by the Worker addon, never closed, canceled or inherited by the native peer/browser scope. The outer driver owns and continuously drains its read end and retains raw bytes outside the destroyed environment. The Node parent emits no competing stdout text during the native phase. This diagnostic sink is independent of the Worker's JS/TSFN and is not the production CDP transport. Its lifetime ends with the parent host, separately from Worker-owned native resources. A blocked/broken diagnostic write is an evidence failure, not permission to omit records.

After it has the actual checkpoint, the native driver sends a single test command through its already owned Node-host stdin. The live parent invokes `worker.terminate()` and records its promise/event result. It does not send a JS stop message to the Worker. Native hook entry must follow the trigger, and the raw log must show no ordinary JS-stop entry before it. Terminating the whole Node host, a prior native drain, Worker process.exit, a synthetic teardown call or OS handle reclamation cannot satisfy N04.

Required post-trigger observations are distinct: cleanup-hook entry; I/O cancellation requests and terminal results; producer exit and join; every channel-authority disposition; hook removal; channel-finalizer observation; both queued IDs discarded exactly once without JS; environment-instance finalizer/release; zero payload leases and active callback frames; control-block destruction after its last consumer; Worker exit/terminate result; original peer wait, inner job zero and every Worker-owned handle/storage result. The Node host must still be alive on its original handle when the outer driver scores these records. Expected Worker termination code 1 is not the Node host's OS exit and is not a failure by itself.

The result checker starts from the two independently fixed peer values and raw wire records, matches their payload IDs through enqueue and disposal, and requires channel-finalizer observation **before both null-env discard records**, with control-block destruction after both and all other lease releases. An aggregate zero is insufficient. Supplemental corrupted copies that move destruction before a discard or omit one terminal ID must be rejected; they do not replace the actual N04 observation. If the two pending payloads do not reach this ordering, preserve the actual sequence and mark this required branch unproved instead of editing the expected order after the run.

Unsettled promises in the destroyed environment are marked `abandoned_by_environment_teardown`, not falsely reported as fulfilled or rejected. Their native dependencies still require receipts. After scoring, the driver releases its host keepalive/input channel and joins the parent's natural process exit. The host process, Worker, peer, inner job, I/O, callback payloads and outer rescue keep separate rows. Any rescue makes the candidate N04 result fail; the outer driver still joins only its original authorities and preserves the unrelated sentinel.

N04 must prove these actual reached states through the same native implementation. The first source review must bind every instrumentation/barrier path and ensure the two-payload queue is truly occupied at the trigger. Queue-full and closing branches are explicitly owned above; no claim is made that N04 necessarily observes both statuses. Their actual occurrences, if any, remain raw results, and source coverage is not mislabeled runtime coverage.
