# Shibuya movement network contract

Phase 6 candidate, 2026-09-08. Owner: network worker. Integration owner: root orchestrator. Base: main `277a833` plus the concurrent renderer pass. Implementation and scoped checks are complete; independent review, integrated traffic behaviour, final gates and landing on main remain the coordinator's acceptance work.

## Interface and authority

`src/world/network-data.ts` defines version 1. `npm run data:network` builds `data/network/network.json`; the Vite middleware serves it at `/network/network.json`. `loadNetwork()` validates before returning. This OSM derivative database remains separate from every PLATEAU mesh and is never included in the Vite bundle. Its source timestamp and three SHA-256 digests bind the OSM extract, terrain mesh and road mesh used to build it.

Every point is in the existing world frame: metres, Y up, X east and Z south, origin at the crossing. `LaneEdge` and `WalkEdge` have stable IDs, endpoint node IDs, sampled points, arc length, width, source way ID, directed successor IDs and optional junction/group IDs. Vehicle edges also hold speed and same-direction lateral neighbours. Lane changes may use only those neighbours; a missing neighbour is not permission to cross a junction or opposing carriageway. Walking paths are directed pairs, with `:f` and `:r` suffixes; render only one of each pair when painting markings. The two populations plan routes through their own `nextIds`; shared coordinates never splice their graphs together.

`SignalController` is the only signal authority. The simulation calls `advance(stepSeconds, occupied)` once per fixed tick before either population updates. It rejects a variable or invalid step. `canEnter(groupId)` gates entry; `snapshot()` reports each junction's stage, active group, amber group, elapsed/remaining seconds, clearance hold and cycle. Amber allows no new entries. Actors that already entered continue clearing on red. Style changes have no signal or network state.

Approach, conflict and exit portions of a lane are separate edges, split analytically at the conflict boundary. Only the conflict portion has `junctionId`; a queue outside does not occupy it. A vehicle's tail can remain inside after its centre reaches an exit edge, so occupancy uses the full committed footprint through `occupiesJunction`, not only the current edge label. Pedestrian staging remains on sidewalk edges with `junctionId: null`, even if the conservative geometric envelope covers that sidewalk. The simulation must count only committed actors, keep pedestrians within their walking corridor, reserve receiving lane space before vehicle entry, and continue tracking clearance across edge transitions. These are consumer obligations; the signal unit tests do not establish that the simulation obeys them.

Overlapping conflict areas share one controller. `Junction.conflictAreas`, when present, is the exact union of the original disks. `radiusM` then bounds that union for display only; it is not an expanded conflict surface. Sampling, entry splitting and occupancy use the union. Independent controllers may not have overlapping physical areas. Merging never feeds an enclosing circle back into the overlap search.

## What comes from data and what is authored

The offline pipeline uses the existing scene meshes as its height instrument. It samples their triangles and resamples paths at no more than 1.5 m horizontally. The road builder's existing lift is retained; no scene mesh is edited. Missing terrain is missing, with the affected path intervals excluded and reported. The decoder now copies byte views explicitly, including Node Buffer; its old Buffer-specific corruption was reproduced before correction.

OSM supplies topology, lane tags, direction tags, access restrictions, sidewalks, crossing paths and surface traffic-signal nodes. Tagged elements win over the bare duplicate records emitted later by Overpass. Underground, elevated, indoor and inaccessible ways are filtered before adjacency. In particular, platform ways `664527469` and `664527472` must not join the surface scramble through shared node `291758776`.

Road lane count defaults to one each way, or one in the tagged one-way direction. Lane width defaults to 3 m, with tagged width divided across the lane count. Actual source tags include four consistent directional lane splits and two explicit widths. Width 1 m on way `136587664` is excluded from vehicle routes rather than widened. Contradictory lane totals and unsupported reversible direction tags fail with a named source error. Bidirectional `lanes=1` requires a future shared narrow-road model and is not silently turned into two lanes; none occurs in this source extract. Left-hand offsets, cubic turn connectors and lane ordering are approximations. They are not surveyed lane boundaries.

The pedestrian network uses mapped surface footway, pedestrian, path, steps and living-street geometry. It does not fabricate a sidewalk alongside every road. Missing corridor widths default to 2.5 m for walking paths, 5 m for pedestrian streets, 3 m for crossings and 5 m for scramble crossings. These widths are inferred movement/render corridors around OSM centrelines, not measured PLATEAU sidewalk surface extents. Painted crossings and pedestrian movement read the same `WalkEdge.points` and width.

OSM way `754454449` supplies the mapped NW-SE diagonal. The authored NE-SW diagonal joins real surface sidewalk endpoints `3608568703` and `3608568744`, uses `sourceWayId: null`, and is listed in the authored-edge diagnostics. Both directions use the scramble controller. The visible crosswalk treatment must distinguish this authored completion from OSM source geometry in provenance.

The conflict extent is authored from the OSM crossing geometry, with a 39 m main scramble envelope and smaller crossing envelopes. A mapped surface signal without a covered crossing receives a conservative 12 m envelope. These are not PLATEAU intersection polygons and are not a traffic survey. The current builder includes all 78 qualifying surface traffic-signal nodes and checks their coverage again after merging. The simulation timings are also authored: no real Tokyo signal schedule is claimed.

Each approach sector has exclusive vehicle green. At the scramble, four approaches receive 16 seconds green, 3 seconds amber and at least 3 seconds empty clearance each. First pedestrian admission is at simulated second 88 in an empty run. Pedestrian entry lasts 25 seconds, followed by at least 3 seconds empty clearance; the next vehicle phase starts at second 116. Occupied clearance extends this schedule until committed actors leave. Other junctions use 12-second vehicle green and 16-second pedestrian entry. The largest current union has five original disks; the largest display bound is 63.112 m, no junction has more than four approach groups, and the longest empty cycle is 116 seconds.

Node-via `only_*` and `no_*` turn restrictions are applied. Seven via-way, conditional or otherwise unsupported restrictions conservatively block their related entry rather than becoming permission. Their relation IDs and reasons remain in the output. This can reduce available routes. It does not claim full OSM conditional traffic-law interpretation.

## Verification bounds and handoff

`npm run data:network` validates the complete current extract, finite local coordinates, sampled arc lengths, endpoint adjacency, successor references, lateral neighbours, known signal ownership, non-overlapping controllers, source digests, full AOI reach, real source signal coverage, both diagonals and the shared subway-node counterexample. It writes output only after validation. The same source and builder produce identical bytes.

`test/network.test.ts`, `test/signals.test.ts`, `test/network-mesh.test.ts` and `test/network-serving.test.ts` pass 25 tests. Their bounds include synthetic lane/direction/restriction/ground-hole fixtures; four complete signal cycles at 60 Hz; held clearance, queued-outside and tail-inside footprints; malformed input; exact Node/browser byte semantics; and actual headless HTTP for the network mount, asset MIME types, traversal refusal and existing full-body Range behaviour. The test server and its temporary directory close in cleanup. No browser or GUI was launched by this worker.

The mesh regression was first run against the old decoder: browser and offset Uint8Array cases passed, while Buffer decoded the header/backing slab as positions, with first float `7.185598589700907e+22` instead of `0`. The corrected decoder uses `new Uint8Array(bytes.subarray(offset)).buffer`, and all three byte-view cases pass. The integration owner records this red proof in canonical learning/devlog documents.

These checks do not prove visual lane placement, correct street furniture, vehicle/pedestrian collision avoidance, receiving-lane capacity, first-person traffic behaviour or performance at 3,000/200 actors. Those belong to the integrated simulation/render acceptance and independent review. This document must not mark those later phases complete.
