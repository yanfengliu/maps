## Smallest implementable contract

1. **Keep one candidate generator and one complete-route validator.** Preserve walk's directed successors, seed stream/order, 120-edge/700-m caps and at most three attempts, including its current stop after a null walk. Replace the body-length viable predicate with source-legality filtering, then apply the following complete-route checks before returning a plan. This replaces an invalid early predicate with a stricter later decision; a raw walk is never an accepted route. No DP planner, extra seeds, widened bounds, legacy production planner or new-policy search is part of this review.

2. **Classify real passage visits by occurrence.** Build through createRoutePassage using the complete unchanged edge order. Scanning in order, the first governed occurrence starts a visit; later governed occurrences with that owner inside that factory passage's entryIndex..lastConflictIndex are internal to it. Preserve every source occurrence, single internal null gap, mapped control and true exit. A different owner or a later visit requires a new admission. The factory remains the source of passage/window truth; do not merge owners or extend a visit across multiple null sections.

3. **Represent admission halts and mapped-control halts separately.** A small pure query consumes the immutable planned route, absolute progress, and an authority-provided read-only state for the exact actor/route generation and exact RoutePassage object. Its result identifies the next admission occurrence plus the nearest uncleared control/absolute halt. A held lease covers only its own actual window on this route. An unentered grant remains usable only while the authority retains it. A boundary-entry prefix with lastConflictIndex -1 covers no ordinary later gate. Missing, expired, foreign, released or old-generation state grants no exemption. An overdue uncleared gate/control is a refusal, not infinity or a backwards correction.

4. **The authority owns control satisfaction.** Add only the read-only view needed to expose exact held-passage identity/window and immutable uncleared-control references; do not expose a mutable cleared set or let the planner mark controls clear. Use controls from the retained passage itself and from future classified visits, avoiding duplicate obligations from overlapping per-occurrence factory objects. A mapped stop/yield persists before and after passage entry until that same authority records measured satisfaction. Stop requires its existing one-second dwell and yield/receiving checks; no inferred satisfaction from distance, lease grant or a boolean committed flag. All halt, seek/request and observe front calculations use the same footprintRadius/vehicleEnvelope authority measure.

5. **One halt candidate per required new visit/control; no backoff search in this increment.** For a new admission use max(0, entryDistance minus authorityRadius), rejecting genuinely negative room before clamping tolerance. For controls use starts[control.routeIndex] plus control.distanceM minus that radius. Use the actual route sample, heading, lateral placement and core body frame/asset/scale to project the whole footprint. At the first unheld admission it must occupy no authority. At a transition it must be beyond the previous visit's last conflict occurrence and physically clear of the old owner and every new/unheld owner, so the old lease can actually release before a different request. Internal mapped stops may remain inside their own retained owner, but not another authority. Fail closed if the exact body frame is unavailable. Preserve existing certified boundary ingress handling; do not manufacture a first-entry grant, skip passage, change source progress or substitute retirement for clearance. A boundary exception must retain its actual existing certified prefix and lifecycle contract.

6. **Use the same validator for portal selection and final route planning.** drivablePortals currently returns raw-walk successes without assembly, routes.ts:352–366. The corrected screen must use a validated maximum supported class envelope and complete validation under its existing deterministic portal seeds and attempt limit. The actor's actual prescribed scale is validated again. Cache keys must include body inputs that affect halt geometry, or omit caching. Cold/boundary selection and trajectories may change intentionally; preserve and report before/after evidence rather than promising identical cold behavior. No scene, footprint, signal, route, demand or scale weakening is permitted.

The shared pedestrian interface is only passage identity/window, logical progress, current authority state and halt obligation. Pedestrian body/support evaluation remains its own policy. Core displayed support traces and logical source route geometry remain distinct inputs; this query must not become another movement solver or alter the pedestrian walking/join work. Vehicle support, A8 and static 24-person allocation are not inherited proofs for one another.
