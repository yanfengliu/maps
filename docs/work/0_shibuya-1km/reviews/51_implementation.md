## Reports

### Codex independent reviewer

**No-go for native capture.** V3 repairs the demonstrated detached-continuation failure: the actual ESM awaits work, retains late acquisition results before the cancellation checkpoint, joins pending listen and close work, and keeps delayed work visibly non-final. The approved 120-second limit bounds work rather than arbitrary in-process drainage. Those improvements do not close F28 because cancellation can still lose a newly created browser descendant.

The independent counterexample starts with admitted browser parent 222. The first owned snapshot precedes `newContext`. That delayed operation creates child 333. The deadline calls `browserServer.close()` immediately, without refreshing descendants. At the seven-second escalation, `forceBrowser()` calls the retained Node `ChildProcess.kill()`. The parent exits; the browser close promise settles. After work settles, `collectOwned()` is skipped because `cancelled` is true. Final `remaining` checks only admitted parent 222 and returns an empty array. The module returns and writes a failed manifest while child 333 remains alive in the fixture. The manifest's `complete` remains false; this is incomplete resource disposal, not fabricated capture success.

This counterexample is grounded in the installed Playwright 1.63.0 implementation. `coreBundle.js` SHA-256 `549070af3acabb3efcc4f55bfe6210f9f7c2fcf633cf7eaa59bfe60719969171`, lines 9330–9440, binds cleanup to parent close and runs Windows `taskkill /T /F` only while the child has neither `killed` nor `processClosed`. Lines 39816–39853 join that process cleanup; lines 57207–57221 expose `BrowserServer.close()` and `.kill()` through it. Node 24.12.0's `internal/child_process` source, SHA-256 `6bf1a45face617fcbdb45741db5ba86f395d84a95164d596a92d837e30df5845`, sets `killed = true` after a successful retained handle kill. Thus the launcher's earlier direct parent kill can disable Playwright's later tree kill. The probe models this source contract; it does not claim an observed Windows orphan or measure its frequency.

Three controls isolate the gap: graceful closure disposing descendants succeeds; admitting child 333 before cancellation lets exact-identity fallback dispose it; the same escalation after an ordinary failure refreshes inventory and also disposes it. The initial counterexample is retained as `independent/cancel-context-parent-only-escalation.json`, SHA-256 `2ad82ded047a512c67a4e68a9ba1330eaf6847afabd5ab92d5ee72a0a727d65b`. The repeat after correcting a separate instrument assertion is `independent-confirmed/cancel-context-parent-only-escalation.json`, SHA-256 `c7e25864889cea913a1830d2f8cd50a63b3398549c3f4e5aabe96f72f2214560`.

Late launch identity refusal remains failure: the exact launcher records `lateIdentityError`, closes the returned browser handle and never reports `complete: true` in that control. Delayed build, listen, launch, connect, CDP, context, page and screenshot cases refuse continuation after cancellation. In particular, an unresolved listen is not memoized as disposed before it later starts listening. A late screenshot is not recorded as a successful frame.

Two extra adversarial exception controls are not additional material findings. Injecting a throwing retained kill followed by rejected browser close reaches the unguarded second await of the memoized `forcedBrowserExit`; it skips final identity fallback and writes no final manifest. The first probe incorrectly asserted that HTTP also remained live; source order had already closed it. The corrected assertion records browser parent/child survival and HTTP closure, preserving the initial script and failed output. Its synthetic `EPERM` label is not the actual Node EPERM contract: Node emits that error and returns false, and Playwright has an error listener. Likewise, an arbitrary HTTP close rejection can leave the synthetic listener live, but the inspected Node `net` implementation's callback error is `ERR_SERVER_NOT_RUNNING`. Neither unrestricted fault injection establishes that corresponding native path.

The smallest repair direction is to refresh and retain exact owned identities before starting closure and again before escalation where the parent remains bindable, including cancellation and late launch. Prefer the existing retained `BrowserServer.kill()` and its joined Playwright disposal over directly killing only its child process. Preserve exact-identity fallback and distinguish unknown inventory from verified absence. A snapshot alone cannot guarantee coverage of children born afterwards; the owned tree-disposal API must retain that responsibility. A successor should demonstrate that the new child counterexample cleans up, ordinary and late acquisition still drain, an inventory failure cannot claim absence, and escalation errors cannot bypass the remaining cleanup. This is read-only advice, not a v4 implementation or acceptance.
