## Findings

**R143-F1 [P2] Count successful reuse, not a first-generation retirement waiting to reenter.** `src/agents/population/tick.ts:2214` computes `reused` as cumulative spawned minus currently enrolled routes; `enrolled()` at lines 2316–2320 excludes the new pending-pedestrian map. At tick 129 of the same one-person short-route fixture used by the submitted reuse test, the first body has completed and its second entry is refused. The exact candidate reports `{spawned:1, retired:1, active:0, generations:1, reused:1}` with `pending:1` and current generation 1. No second activation has occurred, so reuse must still be zero. The submitted test at `test/pedestrian-entry.test.ts:143–154` asserts the other fields but omits `reused`.

Reproduction: `reuse-counter.test.ts` and `reuse-counter-witness.json`; exact-source Vitest result `reuse-counter.json` has one failure, `generation two has only been prepared; no second activation occurred: expected 1 to be +0`. This counter expression predates the patch; the newly introduced ordinary waiting interval exposes its incorrect interpretation of enrollment. Repair accounting so only a successful later activation consumes a reuse, with explicit treatment of the existing vehicle preparation semantics. Gate zero reuse throughout blocked preparation and exactly one after generation 2 activates, without changing spawned/retired/generation conservation or the requested population.

**R143-F2 [P2] The required retry-eligibility failure can pass the submitted gate.** The real guard is `src/agents/population/tick.ts:802`. Removing only `if (state.retryTick > counters.ticks) continue;` in memory leaves all nine new tests passing. The fairness check at `test/pedestrian-entry.test.ts:108–126` requires enough checks and progress, so retrying too often satisfies it. Stable pending state at tick 2 is tested only while the cursor has not returned to that slot; it does not establish the 60-tick retry cadence.

Reproduction: `retry-schedule-bypass.json` is 9/9 green with an exact transform receipt. The independent first case in `contract-probes.test.ts` keeps one otherwise ordinary candidate blocked and records clearance calls. Current source calls at ticks `[1,61,121]`, retains the same body and zero spawned/generation counts, and holds no lease. The mutation calls at every tick from 1 through 180 and fails that probe. Promote an equivalent bounded regression check and retain this red proof. No scheduler rewrite is needed.

**R143-F3 [P2] The live-vehicle helper test does not enforce runtime vehicle occupancy wiring.** The actual population inserts active vehicles at `src/agents/population/tick.ts:795`. Removing that insertion in memory also leaves all nine new tests passing. The vehicle case at `test/pedestrian-entry.test.ts:27–33` manually calls `occupyVehicle` on a standalone space; the default-load entry tests then compare only pedestrian pairs. Together they cannot detect a pedestrian activation path that omits every real vehicle.

Reproduction: `omit-live-vehicles.json` is 9/9 green with an exact transform receipt. The second independent case in `contract-probes.test.ts` observes the real entry space during the first default-vehicle lifecycle. It queries hypothetical pedestrian bodies at active vehicle collision centres that are independently clear of all active pedestrians. Current source refuses them. Omitting runtime vehicle insertion makes the case fail for live vehicle slot 0. Promote this integration check or a stronger real candidate/vehicle conflict fixture, and retain the red proof. This finding is missing regression protection, not evidence that the current insertion is absent or that the synthetic query was an actual collision.
