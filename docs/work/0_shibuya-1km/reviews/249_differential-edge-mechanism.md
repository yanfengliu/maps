The existing shader builds joined normals by gathering the cross products of all actual incident triangles from a world-Float32 position target. The proposed mechanism computes those same geometric triangle edges directly in actor-local coordinates. It does not replace them with skinned source normals, omit tiny faces, cap the influence count, change asset scale or upload CPU-deformed geometry.

For source vertex v and joint j define H(v,j) = weight(v,j) × [inverseBindPoint(v,j), 1], summing if the source repeats a joint. Let I(v) be the retained idle point. Every actual palette is affine with a positive homogeneous W; this was checked for all current and reference matrices. Define A(j) = currentMatrix(j)/currentW(j) − referenceMatrix(j)/referenceW(j). The actor-local source surface is D(v) = I(v) + Σ A(j)H(v,j), which is the original idle + current skin − reference skin law over real arithmetic. The edge b−a is therefore E(a,b) = I(b)−I(a) + Σ A(j)[H(b,j)−H(a,j)]. The sum includes the complete union of both vertices' joints, with no magnitude cutoff.

For every original triangle (a,b,c), compute C = cross(E(a,b), E(a,c)). Gather all incident C values in the original triangle order at each VAT ID, normalize once and rotate by the actor's original quaternion. Translation cancels analytically; the original positive uniform scale cancels in normalization. No compensated world-position arithmetic is used in this normal mechanism.

A WebGL2 implementation can use one triangle-area target and one VAT-ID gather/normalize target, alongside the separate local position pass. Each triangle stores two complete edge term offsets/counts; each term stores a joint index and vec4 coefficient. An explicitly highp `texelFetch` pass evaluates both edges against the 53-joint delta palette and writes their cross product once to an RGBA32F target. A second pass follows all original VAT-ID incident-triangle entries, sums those target values in source order and normalizes/rotates them. The static edge table is prepared once from source geometry. Per frame the CPU uploads only 53 palette differences and the actor transform, not deformed vertices or normals. Draw the actor from local positions through its model/view transform; a world-coordinate target may remain a diagnostic readback. Keeping the draw itself in the old world-Float32 target would retain its quantized edges while shading a different geometric surface, and must not silently inherit this proposal's meaning.

The direct edge table has 126,903 / 16,779 / 3,996 terms in near/medium/far. A raw layout of a joint ID plus four Float32 coefficients per term, two idle edge vectors and three vertex IDs per face costs 3,730,308 / 454,632 / 97,596 bytes before headers, padding, adjacency and GPU targets. This is a concrete cost estimate, not measured allocation or population performance.

The relevant authority supports using all source joint sets and ordinary GPU arithmetic, not a promise of CPU bit identity. glTF explicitly permits subsequent joint/weight sets beyond four influences: [glTF 2.0 skinning](https://registry.khronos.org/glTF/specs/2.0/glTF-2.0.html#skinning). GLSL ES 3.00 specifies highp Float32 storage and operation precision separately: [GLSL ES 3.00, sections 4.5 and 5.11](https://registry.khronos.org/OpenGL/specs/es/3.0/GLSL_ES_Specification_3.00.pdf). A future shader should explicitly qualify numeric texture samplers as highp; their default precision is distinct from `precision highp float`. This source-level observation is **not** a demonstrated cause of either rejected run.

The second and third rows are diagnostics against an **unapproved alternative mathematical reference**, not acceptance. A simple local Float32 buffer has its own error above 1e-5, so merely moving the position target to local coordinates is not enough under that diagnostic. The direct-edge model reduces that measured gap. Its binary64 edge evaluation differs from the original source edges by at most 1.227891e-15 local units; joined normals differ by at most 7.083162e-13. This checks the algebra on every actual triangle and pose rather than only the failing vertex.

The Float32 model rounds coefficients, palette deltas, every dot-product multiply/add, edge sums, cross products, joined sums, quaternion parameters and rotation operations. Its normalization uses JavaScript `Math.hypot` before final Float32 storage; it does not model a compiled GPU inverse square root. Hardware may differ, so the 5.161420e-6 is a CPU-model result only. The largest diagnostic error is far first-liftoff, tick 14, VAT 112; all three incident triangles and their coefficients, actual source points, and computed edges are retained in the second result. The corresponding near maximum is first-liftoff VAT 6431; medium is reverse-walking VAT 714. The original retained GPU worst cases (near turn-landing VAT 13672, medium turn-handback VAT 206 and far turn-handback VAT 299), the fixed near reverse-handback sentinel and the source counterexample VAT 13736 all remain required hardware comparisons.

The algebra requires affine matrices whose bottom row is [0,0,0,W] with positive W, complete weights and inverse-bind points, one shared actor rotation and positive uniform scale. Both probes retain the original reciprocal in source evaluation; the differential palette divides each current and reference matrix by its own actual W before subtraction. It never replaces a value such as 0.9999999999999999 by 1. Projective matrices, nonuniform actor scale or a different reference pose are outside this proof and must be rejected or separately derived. Division before matrix subtraction changes floating-point operation order, so exactness is asserted over real arithmetic and bounded by the measured binary64 residual, not claimed bit identity.
