## Measured cause

The current delay is predominantly main-thread texture preparation, not network transfer, Draco decoding, or cutout geometry. Across the 20.438 s sampled main profile, the source-mapped delight code accounts for 10.362 s self time (50.7% of the span); `delightInPlace` is 10.039 s inclusive and `linearToSrgbByte` is 5.714 s self time within it, so these nested values must not be added. The sign-mask pass is 1.911 s self / 1.994 s inclusive; first-use shader work is 2.015 s self / 2.020 s inclusive; `paint-support` is 1.058 s self; and `createImageBitmap` is 0.653 s self. The cutout-section path is only 0.216 s self / 0.341 s inclusive. The buffered observer saw 71 main-thread long tasks totaling 18.949 s, with a maximum of 2.345 s. Four Draco worker profiles accumulated only 0.301 s of non-idle samples combined, so a broad worker or geometry rewrite is not supported by this run.

This matches the source path. [`rebuild`](../../../../src/scene/facade-textures.ts#L259) reads/resizes each capped atlas, then `delightInPlace` transforms its RGB bytes before creating the replacement texture ([facade-textures.ts](../../../../src/scene/facade-textures.ts#L283), [delight.ts](../../../../src/scene/delight.ts#L283)). Each RGB channel calls `linearToSrgbByte`, whose nonlinear transfer uses exponentiation before rounding to a byte ([delight.ts](../../../../src/scene/delight.ts#L40)). The mask also visits each pixel and evaluates its channel/smoothstep thresholds ([signage.ts](../../../../src/scene/signage.ts#L184)). The renderer’s `parsing` counter spans `parseTile` and `processTileModel`, cache accounting, and model dispatch, not just Draco/glTF decoding ([TilesRendererBase.js](../../../../node_modules/3d-tiles-renderer/src/core/renderer/tiles/TilesRendererBase.js#L1700), [TilesRenderer.js](../../../../node_modules/3d-tiles-renderer/src/three/renderer/tiles/TilesRenderer.js#L793)).

The city remains hidden until all 44 required final leaves are prepared and the visible set is covered ([aoi-cutout.ts](../../../../src/scene/aoi-cutout.ts#L37), [buildings.ts](../../../../src/scene/buildings.ts#L431), [app.ts](../../../../src/app.ts#L225)). Preserve that readiness condition and the approved texture and geometry policy; revealing a partial city or shrinking the accepted atlases would change the contract rather than remove the measured work.

## Bounded optimization proposal

The owner’s rule says GPU-capable work runs on the GPU ([local-rules.md](../../../policies/local-rules.md#L51)). The preferred next experiment is therefore one isolated GPU de-light pass over actual capped atlas bytes, with the current CPU implementation as its reference. Use the existing renderer context rather than opening another WebGL context; the tile hooks can overlap, so the experiment must serialize or otherwise own renderer state, restore that state, and dispose every target/material in `finally`. Include upload, pass setup, readback needed for byte comparison and current post-transform statistics, and texture handoff in the timing. A shader-only timing would not answer whether startup improves.

Keep the run bounded to a representative real atlas first. Compare the complete output RGBA bytes against the CPU reference, including alpha/mask behavior, and record input/output hashes and end-to-end preparation time. GPU floating-point `pow` may quantize some pixels differently from the JavaScript double-precision path; any byte mismatch or net slowdown is a stop condition, not a visual-tolerance waiver. If the single-atlas result is exact and materially faster including readback, the root integration owner can admit a full-scene experiment with the same gate; otherwise revert without broadening the change.

An exact inverse-sRGB byte quantizer (precomputed output thresholds replacing per-channel exponentiation) is a smaller CPU-only candidate and directly targets the 5.714 s hotspot, but it conflicts with the repository’s GPU-first rule as a production implementation. It may serve as a numerical control or comparison only; it must prove byte-for-byte equivalence at all quantization boundaries and against actual atlas outputs. No CPU implementation or GPU contract has been accepted yet.

## Decision

Continue with the texture-conversion path, not renderer orchestration, Draco workers, or section geometry. The prior Vite finding explains the earlier blocked HTML response; the production profile’s 14.48 ms HTML commit rules out a large current pre-document wait in this tested configuration. The remaining fresh production delay is localized to main-thread image preparation, while the original in-app-browser `0 of 44` report remains unreproduced and unexplained. This review proposes an experiment only; it does not accept the map’s broader visual quality or whole-deliverable status.
