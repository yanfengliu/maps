## Reports

### Codex independent motion reviewer

The capture repair is substantively useful, but I reject the frozen candidate for capture-contract acceptance until F23 and F24 are repaired. Both are finite and independently reproduced. Neither requires changing the image estimator or relaxing its bar.

**F23 / P2 — Stale bytes can receive `captureValid: true`.** At `tools/flicker/capture.spec.ts:96`, the manifest predicate checks only `captureFailures.length === 0` and 11 adjacent pairs. Stale-byte refusal lives in `report.failures`, which is copied to the command's aggregate failure list but never added to `captureFailures`. Twelve adjacent, nonblank copies can therefore retain finite moving poses and active non-accumulating post observations while repeating the same PNG bytes. The judge reports 11 byte-identical moving-pair failures, yet the manifest predicate returns true and its capture-failure list is empty. The CPU reproduction uses the actual judge's `frozenRecord(12)` and the exact manifest expression. It does not pretend to be another browser run. The command still exits nonzero, so this finding concerns the false machine-readable capture claim, not a false successful exit or proof of a renderer defect. Carry structural and stale-capture failures into capture validity while keeping residual-model failure separate; cover the complete emitted manifest contract with a failing stale-buffer control.

**F24 / P2 — A failed mouse release skips the pending observer wait.** At `tools/flicker/motion.ts:82-86`, `await page.mouse.up()` precedes `await pending` in the same finally block. If an input command fails and the final release also rejects, JavaScript leaves that block without waiting for the active capture. An independent call to the actual `MotionPath.during` with a deferred capture, a failing third pointer move and a rejecting `mouse.up` returns the release error while `captureSettled` remains false. The reviewer then resolves and awaits that test-owned promise to clean it up. The burst's separate eight-second timer still bounds an otherwise responsive page; this is not a demonstrated permanent process leak. It violates the stated completion/cleanup contract and permits the caller to continue while its observer is still active. Make the observer wait unavoidable even when release fails, retain useful failure information, and cover input failure plus release failure with an actual-method deferred-promise test.

The rendering and observation path otherwise has a coherent finite argument. `RenderLoop.start` queues the next app callback before `advance`, and `advance` increments the frame counter after rendering. The observer queues after that callback and requeues after its copy. `drawImage` and before/after bridge reads run in one synchronous callback. The validator requires equal integer frame counts, identical finite poses and post state, a live active post chain, non-accumulation, native decoded dimensions, and nonflat pixels. The judge requires exact count increments of one and directly compares residual fraction to 0.005. The canvas allocation is bounded to 32 copies, the normal burst is 12, encoding follows the burst, and the observer's own finally cancels its RAF/timer and releases snapshot canvas storage. No camera, render, control-angle, simulation-store, or application-state setter was added.

The input path uses Playwright pointer and wheel commands. It releases the drag before each wheel command, matching the installed OrbitControls state condition. Probe3 has ten pointer acknowledgements inside orbit frames 336-347; ascent frames 604-615 have five pointer and two wheel acknowledgements inside their copied interval, out of six pointer and three wheel commands overall. These acknowledgements identify command completion relative to a last-drawn frame, not the exact frame in which every input took effect. The measured ascent distance changes by `0.27783798389027226` m inside the copied interval. Every final pair moves above the capture floor, and all 24 copy observations are non-accumulating. This establishes the recorded input/capture window, not all-camera or long-duration coverage.

The denominator and claim boundary are improved. Complete common 3x3 support excludes shifted border centres, with explicit compared and excluded counts. For each independent calibration pair, the observed denominator equals `(width - abs(dx) - 2) * (height - abs(dy) - 2)` and sums with excluded pixels to the full image area. The local-refinement boundary and the global search boundary both refuse exhausted searches. The unchanged bar is no longer divided and multiplied by frame gap.

The authored calibration numbers reproduce, and additional controls support the decision to leave `sceneVerdict` unresolved. A separate LCG field, seed 20260919, has 400x300 samples and is bilinearly read into eight 192x108 frames without leaving its support. An exact +2,+2-pixel translation scores zero. Legitimate 0.37,-0.13-pixel translation scores 0.236892-0.465045; 0.0017-radian/frame rotation scores 0.056802-0.129494; two horizontal depth layers at 0.2 and 0.6 pixels/frame score 0.266038-0.293644. All 21 non-integer pairs exceed 0.005 with no texture change.

An additional exact -1,+1-pixel translation of that high-frequency field scores 0.309735-0.314060. The coarse estimator samples every second pixel, so that odd-pixel motion changes the sampled noise population and can select the wrong coarse basin. Five pairs hit a declared search boundary and two return wrong interior shifts. This is retained counterevidence against generalizing the author's zero-residual integer fixture to arbitrary images. It is an estimator scope note, not a demand for estimator redesign in this capture component. It further rules out diagnosing these scene residuals as renderer defects. A future estimator must face such negative controls as well as fractional motion, rotation, parallax, occlusion and positive defects.

The scene claims are appropriately withheld. Replaying probe3 yields 11 residual failures for each path at the unchanged bound, and `sceneVerdict` remains `not-established`. A zero command exit would establish only the lane's finite capture and residual predicates. It would not establish the general moving-scene criterion. The author's native still-image review is attributed and explicitly does not make that temporal claim.
