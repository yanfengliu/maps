## Cost and simpler alternatives

The retained prototype clips 4,668 triangles per wheel against five local road triangles. Its existing log reports 640 wheel evaluations in 2,648.2563 ms: about 16.55 ms per four-wheel pose by arithmetic, not a runtime benchmark. Copying that loop into every display frame would be a substantial CPU cost even for one taxi. Cache pinned wheel geometry, surface candidates and chassis records outside the frame loop. On a certified complete single-plane footprint the same maximum reduces exactly to a transformed-vertex support maximum; that is an implementation of the same contact value, not a second policy. Whether further reduction is needed is a later runtime decision; no performance or optimization work is opened here, and an uncertified offset lookup/lerp is not an acceptable shortcut.

There is no materially simpler local blend, constant offset or phase choice that preserves the present exact-mesh/contact contract. A nominal circle, frozen wheel spin or enlarged tolerance changes that contract or the rendered body. The smallest conceptual solution is one kinematic contact evaluator shared by all candidate consumers, with local proof first. It is materially smaller than a suspension framework, but it does require root to accept the contact-consumer semantic change and its eventual route-wide qualification obligation. Keep first actual pedestrian delivery ahead of that work.
