## Material finding

**[P2] Apply the current style when the asynchronous actor is mounted — `src/app.ts:317-320`.** `createLocalWalker` receives the current style by value, then awaits the private packet, source checks and three GLB loads. During that interval the real World style picker remains active: `setStyle` updates the app's `style` and only its already-registered consumers (`src/app.ts:420-426`). The actor is registered after its await and is never synchronized to the latest style. Consequently a Satellite-to-Cartographic change during loading can finish with a Cartographic city and a photographic actor; the opposite direction likewise leaves a flat actor in Satellite. Other async consumers in this same app explicitly call their `setStyle(style)` when mounted.

Required contract: after its final await and disposal guard, synchronize the returned actor to the app's current style before exposing/mounting it and registering subsequent style changes. Keep the same actor, root, generation and held clock. A narrow production-path regression should hold the real `createApp` actor factory promise unresolved, change style through the app's real setter, resolve it, and verify that the mounted walker receives the latest style; also retain the disposal-before-resolution behavior. Prefer the existing app lifecycle test seam over a new loading framework. The native trial must also use the actual picker during the relevant load window if claiming that real UI path is fixed. Waiting until all loading finishes before toggling does not exercise this defect.

No other material source defect was found in the inspected frozen production change. This finding was sent to root promptly; root agreed it needs repair before admission.
