## Dependency facts and required acceptance cases

**D1 — Zero error is not a whole-city readiness predicate.** `node_modules/3d-tiles-renderer/src/core/renderer/tiles/traverseFunctions.js:187` stops refinement when the error meets the target; `:251-254` still skips an out-of-frustum tile; `:420-424` allows a REPLACE ancestor to become a placeholder while children are not ready. `TilesRendererBase.js:1333-1353` removes queued unused tiles, and `:885-897` clears prior used marks before traversal. The whole-city warmup therefore must drive and verify the exact expected 44 final-leaf identities, including initially off-camera leaves, rather than infer them from `errorTarget = 0`, queue emptiness or the current camera. Acceptance: one delayed off-camera leaf keeps the cutout unrevealed; after all leaves are ready, moving and shrinking the viewport never exposes a coarse source section.

**D2 — Parsed/prepared and admitted/loaded are different states.** `TilesRenderer.js:794-798` awaits model processing before its final resource inventory; `:842-861` can abort afterward; `TilesRendererBase.js:1741-1758` sets LOADED but can immediately discard the tile if the cache was already full; only `:1775-1781` dispatches `load-model`. `traverseFunctions.js:9-11` counts FAILED as download-finished for traversal readiness. Acceptance: readiness tracks live successful loaded identities with their geometry/caps still owned, rejects any failed required leaf, and removes disposed identities; duplicate events or an aborted/rejected prepared tile must not advance a count to 44. An idle queue or `allChildrenLoaded` alone is insufficient.

**D3 — Below the cache floor can retain CPU leaves, but does not pin GPU allocations.** Core `LRUCache.js:349-355` evicts for bytes above its minimum or nodes above its minimum; defaults are 6,000/8,000 nodes (`:65-73`). Thus a complete source resident set below the configured 640 MiB floor with only 67 source records is compatible with CPU retention. This is a measured bound, not a promise under a larger set. `UnloadTilesPlugin.js:117-140,159-192` separately schedules GPU disposal after visibility changes while retaining CPU objects. It calls `material.dispose()` and `geometry.dispose()` for off-screen content and expects later re-upload. Acceptance: the actual cache number includes caps before the first cached measurement; hidden-leaf GPU unload/re-entry preserves clipping/material programs and neither clears semantic readiness nor duplicates caps. `TilesRenderer.js:1006-1016` caches the first byte estimate in a WeakMap, so attaching geometry after that estimate makes the reported headroom stale.

**D4 — Model-processing plugin registration order does not serialize async work.** `TilesRendererBase.js:728-743` starts all hooks and then awaits `Promise.all`; `TilesRenderer.js:794-798` uses it for `processTileModel`. The unchanged facade plugin collects materials at `src/scene/facade-textures.ts:201`, awaits atlas rebuild at `:209`, then traverses the whole scene for procedural attributes/material patches at `:229-234`. Acceptance: cap construction must be explicitly ordered/excluded relative to that work. Delaying an atlas rebuild must not make cap materials or geometry vary with hook completion order. Ready status must follow completion of every required hook. This matters specifically because new section meshes share tile scenes with the existing async facade processor.

**D5 — Local clipping must survive the actual normal/depth/shadow materials.** Primary `src/render/normal-pass.ts:19-27` temporarily replaces all visible mesh materials with an agent selection or one shared ordinary normal material. That drops source local clipping unless the adapter carries it through. Writing per-mesh clipping into that single shared material causes all ordinary meshes to use the last state. Three `WebGLClipping.js:67-75` ignores global planes during shadows; local planes additionally require `clipShadows`. `WebGLShadowMap.js:257-262,320-322` selects custom depth/distance material and then copies clipping from the current visible material. `Material.js:299-305` states that negative signed distance is discarded; the fragment chunk implements this. Acceptance: city geometry, each side cap, sky and selected agent normal materials retain their distinct intended clipping policies, including when the normal draw throws. Beauty/normal/depth/shadow views must agree at every edge; cap vertices on their own clipping plane must not disappear from floating-point sign differences. Root reports the candidate already has separate plane-array variants and a forced-throw control; that implementation has not been inspected here.

**D6 — The loading state must suppress geometry, and reveal must invalidate the temporal image.** Three `WebGLRenderer.js:1711` and `WebGLShadowMap.js:344` stop traversal at `object.visible === false`; an overlay does not. A parent visibility gate can suppress children in both passes without preventing the independent tiles traversal. The primary frame loop calls building update and the stillness predicate before rendering (`src/app.ts:207-220`); `src/render/post.ts:263-269` only resets TAA when stillness becomes false or explicit invalidation runs. Acceptance: delayed loading shows the chosen loading surface with no partial city/shadow residue, then reveal cannot reuse a fully accumulated hidden-world image. Test the ordinary still camera and an actual moving camera through reveal; this is separate from a ready status assertion. The current all-black candidate frame is being diagnosed by the implementation owner; this audit does not attribute its cause.

**D7 — Added pass materials and late geometry have explicit disposal owners.** Three's tile loader inventories ordinary `c.geometry`, `c.material` and its direct textures after processing (`TilesRenderer.js:810-839`), later disposing that stored inventory (`:882-945`). It does not inventory custom depth/distance materials or independently cached normal variants. Core renderer disposal unregisters plugins first (`TilesRendererBase.js:1045-1064`) and only then removes tiles; plugin cleanup cannot assume a later plugin `disposeTile` callback will still run. Acceptance: full app disposal and tile reload dispose each added cap/pass resource once through an explicit owner, remove cached tile readiness and prevent any late async completion from revealing the disposed scene. Retained normal variants should be intentionally shared by immutable policy and released at their owner's disposal, not treated as leaked per-tile objects.
