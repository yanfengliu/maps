# Defect register

## 2026-10-20 — Benches do not match campus seating

Symptom: the user reports that benches are inaccurate. Investigation confirms all benches used the same wood model even when material tags specified concrete; unknown backrest/material and road-derived facing were treated as detailed geometry. The node-only source extraction also omitted mapped bench ways and curved seating. Correction and verification are tracked in [the bench/sculpture record](../work/0_bay-area-stanford/benches-statues.md): preserve source facts, use photo-supported forms, distinguish unknowns, check actual line paths and facing semantics, and inspect native close views.

## 2026-10-20 — Mouse gestures pause held WASD

Symptom: WASD and mouse must move the camera at the same time. Root cause: the first held-input repair deliberately paused keyboard RAF updates during pointer/wheel activity to avoid public camera calls resetting MapLibre's native handlers. That preserved each input separately but prevented composition. The correction merges deltas in the pinned native input pipeline; 40 actual checks cover both inputs being active, both release orders, wheel equivalence and drag event ownership. Restoring the old pause reproduces the failure. [The record](../work/0_bay-area-stanford/simultaneous-environment.md) and [review 007](../work/0_bay-area-stanford/reviews/007_simultaneous-input.md) retain exact hashes and bounds; this supersedes the previous pointer-priority policy.

## 2026-10-20 — WASD stops after one key step

Symptom: holding WASD produces a one-off camera jump rather than continuous movement. Root cause: each canvas keydown calls one animated 100-pixel `panBy`; movement depends on discrete key events/OS repeat instead of elapsed held-key time. The correction uses elapsed-time held-key movement, normalized diagonals, immediate release and focus/lifecycle cancellation. Native pointer and wheel gestures take priority because public `panBy` stops MapLibre handlers. Verification holds one physical key without repeated keydown events and samples late movement; the one-step negative fails. A held-wheel regression found during review also went red, then preserves the exact native zoom delta after correction. All 34 tests and 50 bounded real-input checks pass; [the input/architecture record](../work/0_bay-area-stanford/held-input-architecture.md) retains evidence and limits.

## 2026-10-20 — Stanford landmarks look like generic multistory blocks

Symptom: the user asks for real building floors, windows and distinctive architecture, calling out the campus church. Investigation confirmed Memorial Church used an estimated 24 m envelope and the same repeating procedural façade as ordinary buildings; overlapping Main Quad geometry also hid its lower volumes. Source data has 87 floor-tagged features among 648 and no window-count tags. Correction uses actual Stanford photographs, a dedicated present-day church, low Quad arcades, composed parent/part rendering and distinct source-aware profiles. Bing Wing and Roble get bounded photo corrections. Source metadata stays intact; the UI distinguishes mapped levels, official descriptions and estimates. Independent area/courtyard checks, emitted church portal/window checks and native multi-angle captures cover the defect class; generic church/floor and overlapping-Quad negative controls fail. [The record](../work/0_bay-area-stanford/held-input-architecture.md) and [photo sources](../work/0_bay-area-stanford/architecture-references.md) preserve coverage and unsurveyed limits.

## 2026-10-20 — Embedded browser reports a crashed localhost map

Symptom: the user sees a blank map/loading indicator followed by “This page crashed. Localhost crashed unexpectedly.” in the built-in browser; Chrome loads the app. Scoped host diagnostics record `IAB browser page unresponsive` for `http://localhost:5173` at 16:21:07.696Z and 16:22:10.981Z. The host uses its crash screen for unresponsiveness as well as process termination. No matching process-gone, GPU-crash or out-of-memory diagnostic was found in the inspected logs; the underlying hang cause remains unproven.

Bounded mitigation: defer custom campus shader allocation and compilation until approach zoom 12, instead of running it during the initial regional view. A mock-WebGL regression fails against the old renderer at zoom 9 and passes with deferred setup; separate tests cover approach initialization, asynchronous completion, context recovery and cleanup. This proves removal of unnecessary regional GPU work, not the host hang's root cause. The user reports continued failure at localhost:5174 after that candidate; Chrome still works. Fresh independent investigations are tracked in [the active record](../work/0_bay-area-stanford/held-input-architecture.md). Direct inspection of the built-in tab is blocked by browser security policy, and actual embedded-browser recovery remains unverified. Earlier measurements are in [the navigation/startup record](../work/0_bay-area-stanford/navigation-startup.md).

## 2026-10-20 — Slow development startup

Symptom: the user reported slow loading with `npm run dev` after the Bay Area pivot. Investigation: cold Vite logs showed archived HTML/source discovery and unresolved Shibuya dependencies, despite a 225 ms server-ready message. Root cause: default dependency entry discovery included the retained `artifacts/` tree, and the default watcher also reloaded the active app for archived worktree edits. A second startup pass fetched tiles for a temporary camera before fitting the actual overview; remote font CSS also delayed styles.

Correction: pin Vite discovery to `index.html`, ignore this checkout's retained artifacts/data in its watcher, configure the overview before requesting tiles and remove the remote interface font dependency. Whole-class verification: a real Vite optimizer fixture first fails on an unavailable archived-only import with default discovery, then succeeds with the app configuration. A primary-checkout watcher probe ignores archived HTML changes while observing live public data. Cold headless desktop/mobile startup, early navigation and recovery pass. Bounds and measurements are in [the startup record](../work/0_bay-area-stanford/startup.md).
